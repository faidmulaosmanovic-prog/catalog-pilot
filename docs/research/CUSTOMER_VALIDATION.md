# CatalogPilot — Customer Validation Plan

**Version:** 1.0  

---

## 1. Goals

1. Confirm ICP pain intensity around spreadsheet/catalog ops.  
2. Confirm willingness to try a paid tool (not just “nice idea”).  
3. Learn which channels and file formats matter first.  
4. Recruit 3–10 pilot users for MVP feedback.

---

## 2. Methods

| Method | Count target | Output |
|--------|--------------|--------|
| Problem interviews (30–45 min) | ≥8 before heavy feature build beyond foundation | Notes tagged by pain |
| Artifact tests (CSV sample walkthrough) | ≥5 | Usability friction list |
| Paid pilots | ≥3 | Retention + feature requests |
| Landing waitlist (optional) | Track conversion | Messaging tests |

---

## 3. Interview script (outline)

1. Role, catalog size, channels.  
2. Walk through last time they onboarded a supplier file or fixed listing errors.  
3. Tools used today; cost (tools + labor).  
4. What breaks most: barcodes, images, categories, channel templates?  
5. Show positioning statement — reaction.  
6. Price sensitivity (van Westendorp light or simple “too expensive at?”).  
7. Ask for pilot interest + sample anonymized CSV.

**Do not** pitch features for the first half of the call.

---

## 4. Pass/fail gates

| Gate | Pass criteria |
|------|---------------|
| G0 Problem | ≥6/8 interviewees describe recurring spreadsheet/catalog pain without prompting |
| G1 WTP signal | ≥4/8 would trial a paid tool in this category |
| G2 Channel priority | Clear majority channel pair for export MVP |
| G3 Pilot | ≥3 orgs agree to use MVP on real (or sanitized) data |
| G4 Activation | Pilots complete import→export within first sessions |
| G5 Revenue | ≥3 paying after trial (or paid pilot invoices) |

Failing G0–G1 → revisit positioning before Phase 4–8 investment depth.  
Foundation/auth work may proceed in parallel cautiously.

---

## 5. Pilot program design

- **Duration:** 30 days  
- **Price:** discounted **[Hypothesis: 50% off]** in exchange for biweekly calls  
- **Success:** weekly active import/validate/export usage  
- **Data:** prefer sanitized catalogs; sign simple pilot terms  

---

## 6. Metrics to capture

- Catalog size, channels, current tools  
- Time spent weekly on catalog ops (self-reported)  
- Must-have vs nice-to-have feature tags  
- Objections (trust, AI, lock-in, price)  

Store raw notes privately; synthesize themes monthly into PRD updates.

---

## 7. Ethics & privacy

- No pressure to upload PII  
- Delete pilot files on request  
- Disclose subprocessors if asked
